# Fact Knowledge Layer

Extracts checkable claims from PDFs, proves every claim against its source text,
and decides whether claims from different documents corroborate each other,
contradict each other, or only appear to conflict because they measure different
things.

**The core engine is deterministic and runs with no API key.** No LLM reads a
PDF, extracts a claim, or decides a relationship. One can optionally adjudicate
the small number of pairs the rules explicitly mark ambiguous;
`FKL_STRICT_DETERMINISTIC=1` refuses even that. Nothing in the pipeline is
specific to a document, a company, or a metric.

**The four required cases, as real system output:
[`samples/REQUIRED_CASES.md`](samples/REQUIRED_CASES.md)** — generated by
`scripts/export_samples.py`, every quote located programmatically in the source
PDF, every example picked by rule rather than by hand.

## 1. Setup and Run Instructions

Python 3.11+. No API key, no database server, no build step.

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
```

**Quickstart (~20 s)** — ingests two PDFs and boots the UI at
<http://127.0.0.1:8000>, with enough in the store to show every verdict type:

```bash
./scripts/quickstart.sh
```

**Or run the UI on its own:**

```bash
.venv/bin/python scripts/serve.py
```

Drop a PDF anywhere on the page. Ingest runs as a background job with live
progress. **Relationships** shows each verdict as one card: both claims in a
single aligned grid — value, then a row per context field, with disagreeing
rows banded — over the explanation, the step-by-step reasoning trace, and the
counterfactuals. Each side's evidence has a "View in source PDF" toggle that
renders the exact region of the exact page with the claim's bbox drawn on it.
**Claims** and **Needs review** are scannable lists, one line per fact.

**From the command line:**

```bash
# ingest PDFs, then build cross-document relationships
.venv/bin/python scripts/ingest.py path/to/*.pdf --relate

# the whole starter corpus (6 PDFs, 511 pages) -- about 95 seconds
.venv/bin/python scripts/ingest.py starter-datasets/*/*.pdf --relate
```

**Tests** — 114, of which the integration suite re-ingests three real PDFs and
asserts the live store holds one relationship of each required kind, that both
claims carry real evidence, that every verdict was decided by rules rather than
a model, and that at least one extraction failure was surfaced:

```bash
.venv/bin/python -m pytest          # unit suite, offline, fast
.venv/bin/python -m pytest -m ""    # everything, including integration
```

**No API key is used.** The system ships with the LLM path switched off, and
every number in this README was produced without one. The adjudicator code
remains in the tree because the measurements below compare against it, but it
is inert unless `FKL_ENABLE_LLM_FALLBACK=1` is set with a provider configured;
`FKL_STRICT_DETERMINISTIC=1` refuses it outright.

## 3. Approach

### Architecture

```
PDF ──> structured pages ──> rule-based claim extraction ──> grounding
        (PyMuPDF/pdfplumber:   (sentence rules +              (locate the evidence
         text, coordinates,     table reconstruction)          for real; quarantine
         headings, tables)                                     what cannot be located)
                                                                      │
        ┌─────────────────────────────────────────────────────────────┘
        ▼
   entity gate ──> predicate gate ──> context comparison ──> verdict
   (two independent gates)            (period / unit / scope / basis /
                                       denominator / modality)

   corroboration · contradiction · reconciled · supersedes ·
   component_of_total · partial_cover · underspecified
                                          │
                                  ambiguous only, opt-in ──> LLM
```

### The central decision: extract claims, not facts

A fact flattened to a value cannot be compared safely. `8,142` and `2,076` look
like a contradiction until you know one is a full year and the other a quarter.
So the unit of extraction is a **claim**, carrying the context that makes it
comparable:

```json
{
  "subject": "Delhivery Limited",
  "predicate": "revenue from customers",
  "value": "8,142", "value_num": 81420000000.0, "unit": "INR crore",
  "context": { "period": "FY24", "scope": null, "basis": null,
               "geography": null, "as_of": null, "denominator": null },
  "modality": "reported",
  "evidence": { "page": 14, "text": "Revenue from customers(1) | FY24 | 8,142",
                "char_span": [1183, 1208], "bbox": [138.6, 170.8, 472.5, 184.2] },
  "confidence": { "extraction": 0.88, "grounding": 1.0 }
}
```

A null context field means *the document did not say*, which is not the same as
the documents disagreeing. **Missing context can never, on its own, produce a
contradiction** — it produces `underspecified`.

### Decisions worth naming

- **Deterministic core.** The earlier version of this system used an LLM to
  extract claims. It was slower, rate-limited, unrepeatable, and — worst —
  its errors were unauditable. Rules are auditable: every verdict carries the
  rule that produced it.
- **Grounding is a gate, not a score.** A claim whose quote cannot be relocated
  in the page text is quarantined out of the shared layer rather than admitted
  with a low number. Fabricated and stitched-together quotes are rejected by
  construction.
- **Two independent gates.** Entity and predicate matching are separate: same
  subject with a different property is not a comparison, and neither is the same
  property about different subjects.
- **Rule IDs, not just verdict names.** Every relationship names the rule
  (`R50`, `R12`…) that decided it, so a wrong verdict is traceable to one rule
  rather than to "the system".
- **Counterfactuals.** For any relation the system answers *what would change
  this?* by re-running the cascade with one qualifier ablated at a time, and
  reports only the ablations that actually change the outcome.
- **Confidence is four numbers** — extraction, grounding, matching,
  relationship. A verdict is bounded by the weaker of the two claims, so a shaky
  extraction cannot become a confident contradiction just because two numbers
  differ.
- **Incremental by construction.** A new document is compared only against
  existing claims; nothing is recomputed. Re-ingesting an identical file is
  skipped by content hash.

### Measured results

Full starter corpus, deterministic, no API key (raw measurements:
[`samples/BENCHMARK_full_deterministic.md`](samples/BENCHMARK_full_deterministic.md),
three-mode comparison in [`samples/BENCHMARK.md`](samples/BENCHMARK.md)):

| metric | value | | relationships | count |
|---|---|---|---|---|
| PDF pages read | 511 | | `partial_cover` | 11,848 |
| claims extracted | 4,794 | | `reconciled` | 1,858 |
| grounded / quarantined | 4,706 / 88 | | `component_of_total` | 1,599 |
| tables reconstructed | 430 | | `underspecified` | 1,374 |
| candidate pairs compared | 22,052 | | `supersedes` | 102 |
| relationships stored | 16,823 | | `corroboration` | 40 |
| LLM calls / runtime | **0** / **~95 s** | | `contradiction` | **2** |

Against the LLM-based pipeline it replaced, same machine and corpus:

| | deterministic | LLM-based |
|---|---|---|
| full corpus (511 pages) | **98 s** | ~3 hours (rate-limited, never completed) |
| Q4 deck (27 pages) | **1.4 s**, 519 claims | minutes, 43 claims from 12 pages |
| API calls | **0** | ~163 |

At small scale the LLM path does run. On the same 8 pages it extracts more
claims than the rules (44 vs 13) at roughly **150x the wall time** — a real
advantage, worth stating plainly, at a cost the hybrid mode exists to split:
rules first, model only on pages the rules could not read.

### AI tools used

- **Claude Code (Opus 5)** as an engineering partner throughout: architecture,
  implementation, and — most usefully — inspecting real intermediate output at
  each stage, which is how most of the defects below were found.
- **Groq (`openai/gpt-oss-120b`)** for the earlier LLM extraction pipeline this
  architecture replaced, and now only for optional adjudication.

## 4. Limitations and Next Steps

**The two contradictions are real, and finding them cost six fixes.** The RBI's
Combined credit-deposit ratio disagrees with the IMF's Financial Soundness
Indicator by 2.7% in 2023-24 (78.1 vs 80.3) and 2.1% in 2024-25 (79.1 vs 80.8).
In 2022-23 the same pair *corroborates* (75.8 = 75.8), so this is not one stuck
finding — the system separates the years that agree from the years that do not.
An earlier version reported **10** contradictions; all but these were false,
and each was hidden behind the one before it. The most instructive: entity
detection had elected the *publisher* rather than the topic, so the RBI's
claims never met the IMF's at the entity gate. The fix is a property of English,
not of these PDFs — proper names take no article ("India's exports") while
institutions referring to themselves do ("the Reserve Bank conducted"). Measured
across all six documents the ratio separates cleanly, and entity detection went
from four of six documents correct to five of six.

What does not work yet:

- **Entity detection is wrong on one of six documents** — the Economic Survey is
  attributed to `Government` rather than `India`.
- **Predicate matching is lexical.** It cannot bridge institutional vocabularies
  that name the same quantity differently ("gross NPA ratio" vs "non-performing
  loans to total loans"), so those pairs are never compared. **Next:** a
  measure-kind lexicon keyed on the normalised unit and denominator.
- **`partial_cover` and `component_of_total` share the output.** 11,848
  partial-cover rows are mostly noise a reviewer must scroll past. **Next:**
  suppress them from the default view.
- **Two-column documents extract poorly.** Tables survive; prose does not,
  because reading order interleaves the columns. **Next:** order text by column
  before sentence segmentation.
- **No OCR.** Scanned or image-only PDFs yield nothing.
- **Sentence recall is well below table recall** (4,143 of 4,794 claims come
  from tables). The sentence rules need a label-verb-value pattern that much
  real writing does not follow.
- **Percentages without a stated denominator** are marked `underspecified`
  rather than compared — deliberate, but it also skips genuine share-vs-share
  comparisons.
- **Relationships are cross-document only.** Intra-document contradictions (a
  director active on page 5, resigned on page 90) are not surfaced, though the
  machinery supports it.

Case 4 of the assignment — an extraction failure and its handling — is written
up with its evidence in
[`samples/REQUIRED_CASES.md`](samples/REQUIRED_CASES.md).

## 5. Additional Notes

### Repository layout

```
fkl/
  pdf.py            structured pages: lines, coordinates, headings, furniture
  tables.py         multi-strategy table reconstruction + quality scoring
  lexicon.py        general-language vocabulary (auditable: no domain terms)
  extract_rules.py  sentence and table claim extraction
  normalize.py      magnitudes, currencies, percentages, fiscal periods
  ground.py         evidence verification and quarantine
  entity.py         deterministic entity matching
  predicate.py      deterministic predicate matching
  match.py          blocking: entity cluster -> predicate token -> measure kind
  compare.py        context-aware comparison, seven verdicts, reasoning traces
  extractors.py     ClaimExtractor interface (deterministic | hybrid | llm)
  adjudicate.py     optional LLM fallback, isolated from the pipeline
  pipeline.py       ingest and relationship orchestration, resume
  store.py          SQLite, additive migrations
  api.py            FastAPI: JSON API, source-PDF previews, static UI
  web/              React + htm from a CDN, Tailwind play build, no bundler
scripts/            serve.py, ingest.py, quickstart.sh, benchmark.py, replay.py,
                    export_samples.py, inspect_run.py, check_llm.py
tests/              114 tests: unit suite plus the integration acceptance test
```

### On not hard-coding

There is no reference anywhere in `fkl/` to a company, a document, a filename, a
page number, or a metric name. The rules key off document structure (headings,
tables, captions, page furniture) and general English patterns. The one place a
word list exists is `fkl/lexicon.py`, deliberately separated so it can be
reviewed for exactly this. Both starter corpora — a logistics company's filings
and three institutional macroeconomics reports — run through the identical code
path, and a test asserts the macro corpus works without corpus-specific rules.

### Credentials

No credentials are in the repository. `.env` is gitignored and the default
configuration needs none. The four required cases are committed under
`samples/` so the results can be read without running anything.
